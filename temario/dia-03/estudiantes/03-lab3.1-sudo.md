# Lab 3.1 — Delegar con `sudo`

Todos corren cada comando; después lo leemos juntos. Objetivo: que el grupo `soporte` pueda reiniciar y consultar **un** servicio (`chronyd`, el de la hora), y nada más. Todo queda en el log.

---

## Parte 1 — `su` vs `su -`

Ejecutar como `ana`, de las dos formas, el comando `pwd; echo "HOME=$HOME MAIL=$MAIL"` (con `-c`).

**Comprobar:**
```
/home/student
HOME=/home/ana MAIL=/var/spool/mail/student
/home/ana
HOME=/home/ana MAIL=/var/spool/mail/ana
```
Sin guion, ana hereda la carpeta y el buzón de `student`.

---

## Parte 2 — Shell de root con tu contraseña

`sudo -i`. Adentro: `whoami`, `pwd`, `umask`. Salir.

**Comprobar:** `root`, `/root`, `0022`.

---

## Parte 3 — pedro no tiene privilegios

Entrar como `pedro` (`su - pedro`). Adentro: `sudo -l` (pide **su** contraseña), después `sudo cat /etc/shadow`. Salir.

**Comprobar:** `Sorry, user pedro may not run sudo on rhel01.` y `pedro is not in the sudoers file. This incident will be reported.`

---

## Parte 4 — La regla

1. Crear el archivo `/etc/sudoers.d/soporte` con `sudo visudo -f`. Abre `vim`. Escribir **exactamente** esta línea:
   ```
   %soporte ALL=(root) /usr/bin/systemctl restart chronyd, /usr/bin/systemctl status chronyd
   ```
   Guardar y salir (`Esc` `:wq`).
2. Validar la sintaxis: `sudo visudo -c`.
3. Ver los permisos del archivo nuevo.

**Comprobar:**
```
/etc/sudoers: parsed OK
/etc/sudoers.d/soporte: parsed OK
-r--r-----. 1 root root ... /etc/sudoers.d/soporte
```
Si `visudo` dice `syntax error` y pregunta `What now?`: `e` vuelve al editor para corregir. **Nunca `Q`.**

---

## Parte 5 — Probar como pedro

Entrar como `pedro`. Adentro, en este orden:
1. `sudo -l`
2. `sudo systemctl restart chronyd`
3. `systemctl is-active chronyd`
4. `sudo systemctl restart sshd`
5. `sudo cat /etc/shadow`
6. Salir.

**Comprobar:** el 1 lista los dos comandos permitidos. El 2 no imprime nada (éxito). El 3 dice `active`. El 4 y el 5: `Sorry, user pedro is not allowed to execute ...`.

---

## Parte 6 — laura sigue sin nada

Desde `student`: ver qué puede ejecutar `laura` y qué puede ejecutar `pedro` (sin conocer sus contraseñas).

**Comprobar:** `User laura is not allowed to run sudo on rhel01.` Para pedro, la línea con los dos `systemctl`.

## Parte 7 — El rastro

1. Las últimas 6 líneas de `sudo` en `/var/log/secure`.
2. Lo mismo en el journal: `sudo journalctl -t sudo --since "1 hour ago" --no-pager | tail -4`.

**Comprobar:** líneas con `pedro : user NOT in sudoers`, `pedro : TTY=... COMMAND=/usr/bin/systemctl restart chronyd` y `pedro : command not allowed ; ... COMMAND=/usr/bin/systemctl restart sshd`.
