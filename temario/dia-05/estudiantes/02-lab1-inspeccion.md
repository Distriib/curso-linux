# Lab — Inspección de la VM

Leer toda la red del servidor sin cambiar nada. Cada comando responde una pregunta distinta.

---

## Parte 1 — ¿Qué tarjetas tengo y con qué IP?

**¿Cómo veo las tarjetas de red y sus direcciones, en versión corta?**

```bash
ip -br a
```

Ahora ustedes: la versión larga, `ip addr`. Foto.

**Comprobar:**
```
lo        UNKNOWN   127.0.0.1/8 ::1/128
enp0s3    UP        10.0.2.15/24 fe80::.../64
```
En UTM la tarjeta se llama `enp0s1`. **Anoten el nombre: se usa el resto del día.**

---

## Parte 2 — ¿Hay cable?

```bash
ip link
```

**Comprobar:** en la línea de `enp0s3` aparece `LOWER_UP` y `state UP`.

---

## Parte 3 — ¿Por dónde salgo?

**¿Cuál es mi gateway?**

```bash
ip route
```

**Comprobar:**
```
default via 10.0.2.2 dev enp0s3 proto dhcp src 10.0.2.15 metric 100
10.0.2.0/24 dev enp0s3 proto kernel scope link src 10.0.2.15 metric 100
```

---

## Parte 4 — ¿Llego al gateway y a internet?

```bash
ping -c 3 10.0.2.2
ip neigh
```

Ahora ustedes: `ping -c 3 8.8.8.8`. Foto.

**Comprobar:** `0% packet loss` en los dos, y en `ip neigh` el gateway como `REACHABLE`.

---

## Parte 5 — ¿Qué camino recorre un paquete?

```bash
tracepath -n 8.8.8.8
```

**Comprobar:** responde el salto 1 (`10.0.2.2`) y los demás dicen `no reply`. Es lo esperado en NAT; no es un error.

---

## Parte 6 — ¿Quién está escuchando en mi servidor?

**¿Qué programas tienen un puerto abierto?**

```bash
sudo ss -tulpn
```

Ahora ustedes: las conexiones establecidas, `ss -tan`. Foto.

**Comprobar:** en la primera aparecen al menos `sshd` en el `22`, `chronyd` en el `323` y `httpd` en el `80`. En la segunda, su propia sesión SSH como `ESTAB`, con origen `10.0.2.2`.

---

## Parte 7 — ¿Cómo se llama el servidor y cómo resuelve nombres?

```bash
hostname
cat /etc/hosts
cat /etc/resolv.conf
grep hosts: /etc/nsswitch.conf
```

**Comprobar:**
```
rhel01
127.0.0.1   localhost localhost.localdomain localhost4 localhost4.localdomain4
# Generated by NetworkManager
nameserver 10.0.2.3
hosts:      files dns myhostname
```
La línea de `nsswitch.conf` dice el **orden**: primero `/etc/hosts`, después el DNS.

---

## Parte 8 — La vista de NetworkManager

```bash
nmcli device status
nmcli connection show
```

Ahora ustedes: `nmcli device show enp0s3`. Foto.

**Comprobar:**
```
DEVICE  TYPE      STATE                   CONNECTION
enp0s3  ethernet  connected               enp0s3
lo      loopback  connected (externally)  lo
```
A la izquierda la **tarjeta**; a la derecha el **perfil** que tiene aplicado. Acá se llaman igual; más tarde no.

---

# Solución — todos los comandos

```bash
# Parte 1 — tarjetas y direcciones
ip -br a
ip addr

# Parte 2 — enlace
ip link

# Parte 3 — rutas
ip route

# Parte 4 — gateway e internet
ping -c 3 10.0.2.2
ip neigh
ping -c 3 8.8.8.8

# Parte 5 — camino
tracepath -n 8.8.8.8

# Parte 6 — quién escucha
sudo ss -tulpn
ss -tan

# Parte 7 — nombre y resolución
hostname
cat /etc/hosts
cat /etc/resolv.conf
grep hosts: /etc/nsswitch.conf

# Parte 8 — NetworkManager
nmcli device status
nmcli connection show
nmcli device show enp0s3
```
