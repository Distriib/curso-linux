# 2 — Inspeccionar: leer la red antes de tocarla

**La regla del día: primero mirar, después cambiar.**

## Interfaces y direcciones

```bash
ip addr
ip -br a
```

`-br` = *brief*, la versión corta. Sale una línea por tarjeta:

```
lo        UNKNOWN   127.0.0.1/8 ::1/128
enp0s3    UP        10.0.2.15/24 fe80::a00:27ff:fe4c:9b1e/64
```

| Parte | Qué es |
|---|---|
| `lo` | el loopback: la máquina hablándose a sí misma. Siempre `127.0.0.1` |
| `enp0s3` | la tarjeta de red. En UTM se llama `enp0s1` |
| `UP` | la tarjeta está levantada |
| `10.0.2.15/24` | la IP y la máscara |
| `fe80::...` | la dirección IPv6 local del cable |

## Enlace

```bash
ip link
```

`LOWER_UP` = hay cable conectado. Si dice `NO-CARRIER` o `state DOWN`, el problema es físico o del hipervisor, no de configuración.

## Rutas

```bash
ip route
```
```
default via 10.0.2.2 dev enp0s3 proto dhcp src 10.0.2.15 metric 100
10.0.2.0/24 dev enp0s3 proto kernel scope link src 10.0.2.15 metric 100
```

- **Primera línea:** la ruta por defecto. "Todo lo que no sé a dónde va, se lo doy a `10.0.2.2`".
- **Segunda línea:** la crea el sistema solo. "A la red `10.0.2.0/24` llego directo por esta tarjeta".

## Vecinos y conectividad

```bash
ping -c 3 10.0.2.2
ip neigh
ping -c 3 8.8.8.8
```

`ip neigh` es la libreta de direcciones físicas: muestra la MAC del gateway una vez que se le habló. Si dice `FAILED`, la VM no consigue ni hablar con su router.

## Camino hasta un destino

```bash
tracepath -n 8.8.8.8
```

En NAT es normal que solo conteste el primer salto (`10.0.2.2`) y el resto diga `no reply`: el hipervisor no reenvía esas respuestas.

## Quién escucha en la máquina

```bash
sudo ss -tulpn
```

| Opción | Qué hace |
|---|---|
| `-t` | TCP |
| `-u` | UDP |
| `-l` | solo los que están escuchando |
| `-p` | qué programa es (necesita `sudo`) |
| `-n` | números en vez de nombres |

```
tcp LISTEN 0 128  0.0.0.0:22  0.0.0.0:*  users:(("sshd",pid=890,fd=3))
tcp LISTEN 0 511        *:80        *:*  users:(("httpd",pid=1204,fd=4))
```

`0.0.0.0:22` = sshd escucha en todas las IPs de la máquina, puerto 22.

## Nombre y resolución

```bash
hostname
hostnamectl
cat /etc/hosts
cat /etc/resolv.conf
grep hosts: /etc/nsswitch.conf
```

La primera línea de `/etc/resolv.conf` dice `# Generated by NetworkManager`: **ese archivo no se edita a mano**.

## La vista de NetworkManager

```bash
nmcli general
nmcli device status
nmcli connection show
nmcli device show enp0s3
```

Distinción clave, y es la base de todo el bloque siguiente:

| | Qué es |
|---|---|
| **device** | la tarjeta (`enp0s3`) |
| **connection** | el perfil de configuración que se le aplica |

Una tarjeta puede tener varios perfiles guardados, pero solo uno activo.

---

`ip` reemplaza a `ifconfig` y `route`; `ss` reemplaza a `netstat`. Los viejos ni siquiera están instalados en RHEL 9.
