# Lab — El clásico: mv, 403 y restorecon (comandos)

Vos primero, ellos después, foto. Apache tiene que estar `active` en el 80 (Lab 2.1, Parte 3).

## Parte 1 — Crear la página en /root y moverla
```bash
echo "<h1>Portal institucional - version 2</h1>" | sudo tee /root/index.html
sudo ls -Z /root/index.html
sudo mv /root/index.html /var/www/html/index.html
```
El `ls` lleva `sudo` porque `/root` no se puede leer como `student`. El `mv` pisa el `index.html` anterior: está bien.

## Parte 2 — El síntoma
```bash
curl -I http://localhost
ls -l /var/www/html/index.html
ls -Z /var/www/html/index.html
```
Dar el minuto de la pregunta. Qué decir: "permisos 644, dueño root, todos leen… y 403. Miren el tipo: `admin_home_t`. Es un archivo 'de /root' aunque esté en `/var/www/html`. Apache no puede leer cosas de /root."

## Parte 3 — Ver la denegación y corregir
```bash
sudo ausearch -m AVC -ts recent | tail -1
sudo restorecon -v /var/www/html/index.html
curl http://localhost
```
En el AVC puede decir `{ getattr }` o `{ read }` según dónde tropezó Apache: da igual. Señalar `comm="httpd"`, `tcontext=...admin_home_t`, `tclass=file`.
Qué decir del `restorecon`: "cambió solo el tipo. `unconfined_u` sigue ahí y no molesta."

## Parte 4 — cp, cp -a y mv -Z
```bash
echo "<p>aviso</p>" | sudo tee /root/aviso.html
sudo cp /root/aviso.html /var/www/html/aviso-cp.html
sudo cp -a /root/aviso.html /var/www/html/aviso-cpa.html
sudo mv -Z /root/aviso.html /var/www/html/aviso-mvZ.html
ls -Z /var/www/html/
sudo rm /var/www/html/aviso-cp.html /var/www/html/aviso-cpa.html /var/www/html/aviso-mvZ.html
```
`cp -a` ("archive") copia conservando todo: permisos, dueño, fechas y **etiqueta**: por eso queda mal. `mv -Z` mueve y pone la etiqueta del destino. Qué decir: "la regla práctica es una sola: después de mover contenido a una carpeta de un servicio, `sudo restorecon -Rv carpeta`."
