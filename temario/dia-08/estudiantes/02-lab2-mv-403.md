# Lab 2.2 — El clásico: mv, 403 y restorecon

Vamos a reproducir el error más frecuente de SELinux en servidores web (un archivo con permisos perfectos que da 403) y a corregirlo con un solo comando.

---

## Parte 1 — Crear la página en /root y moverla

**¿Qué etiqueta tiene un archivo creado en /root?**

```bash
echo "<h1>Portal institucional - version 2</h1>" | sudo tee /root/index.html
sudo ls -Z /root/index.html
sudo mv /root/index.html /var/www/html/index.html
```

Ahora ustedes: lo mismo. Foto.

**Comprobar:**
```
unconfined_u:object_r:admin_home_t:s0 /root/index.html
```

---

## Parte 2 — El síntoma

**Permisos 644, dueño root, todos pueden leer. ¿Por qué 403?**

```bash
curl -I http://localhost
ls -l /var/www/html/index.html
ls -Z /var/www/html/index.html
```

Ahora ustedes: lo mismo. Foto.

**Comprobar:**
```
HTTP/1.1 403 Forbidden
...
-rw-r--r--. 1 root root 42 ... /var/www/html/index.html
unconfined_u:object_r:admin_home_t:s0 /var/www/html/index.html
```
El tipo es `admin_home_t`: la etiqueta viajó con el archivo. Apache (`httpd_t`) no puede leer cosas de `/root`, estén donde estén.

---

## Parte 3 — Ver la denegación y corregir

**¿Qué dice SELinux que negó, y cómo se arregla?**

```bash
sudo ausearch -m AVC -ts recent | tail -1
sudo restorecon -v /var/www/html/index.html
curl http://localhost
```

Ahora ustedes: lo mismo. Foto.

**Comprobar:**
```
type=AVC msg=audit(...): avc:  denied  { getattr } for  pid=... comm="httpd" path="/var/www/html/index.html" ... scontext=system_u:system_r:httpd_t:s0 tcontext=unconfined_u:object_r:admin_home_t:s0 tclass=file permissive=0
Relabeled /var/www/html/index.html from unconfined_u:object_r:admin_home_t:s0 to unconfined_u:object_r:httpd_sys_content_t:s0
<h1>Portal institucional - version 2</h1>
```
En el AVC: `comm="httpd"` intentó algo sobre un `file` con `tcontext=...admin_home_t`. `restorecon` cambió solo el **tipo**, y con eso alcanzó.

## Parte 4 — cp, cp -a y mv -Z

**¿Cuál de estas tres formas de llevar un archivo deja la etiqueta bien?**

```bash
echo "<p>aviso</p>" | sudo tee /root/aviso.html
sudo cp /root/aviso.html /var/www/html/aviso-cp.html
sudo cp -a /root/aviso.html /var/www/html/aviso-cpa.html
sudo mv -Z /root/aviso.html /var/www/html/aviso-mvZ.html
ls -Z /var/www/html/
sudo rm /var/www/html/aviso-cp.html /var/www/html/aviso-cpa.html /var/www/html/aviso-mvZ.html
```

Ahora ustedes: lo mismo. Foto.

**Comprobar:**
```
unconfined_u:object_r:httpd_sys_content_t:s0 aviso-cp.html
unconfined_u:object_r:admin_home_t:s0 aviso-cpa.html
unconfined_u:object_r:httpd_sys_content_t:s0 aviso-mvZ.html
unconfined_u:object_r:httpd_sys_content_t:s0 index.html
```
`cp` hereda del destino (bien). `cp -a` conserva **todo**, incluida la etiqueta (trampa frecuente en scripts de despliegue). `mv -Z` mueve y reetiqueta según el destino. Regla práctica: después de mover contenido a una carpeta de servicio, `restorecon -Rv` siempre.
