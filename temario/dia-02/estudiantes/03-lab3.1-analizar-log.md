# Lab 3.1 — Analizar un log de 300 líneas

Se hace por partes, solos. Llega un log de un servidor y hay que responder preguntas de soporte con `grep`, `cut`, `sort`, `uniq`, `wc` y redirección. Cada parte tiene un **Comprobar**.

El log tiene este formato, un evento por línea:
```
FECHA       HORA     NIVEL USUARIO SERVICIO   MENSAJE
2026-03-17  04:51:09 INFO  carlos  httpd      Tarea completada
```
---

## Parte 1 — Generar el log

El instructor pega en el chat un bloque que empieza con `cat > ~/empresa/genera-log.sh` y termina con `FIN`. Copiarlo **entero**, pegarlo en la terminal, Enter. Después:

```bash
bash ~/empresa/genera-log.sh > ~/empresa/logs/servidor.log
cd ~/empresa/logs
wc -l servidor.log
md5sum servidor.log
```

**Comprobar:** `300 servidor.log`, y el `md5sum` tiene que ser **igual** — si es igual, todos tienen exactamente el mismo archivo y los números que siguen van a coincidir.

---

## Parte 2 — Mirarlo

1. Ver las 3 primeras líneas y las 3 últimas.
2. Abrirlo con `less`, buscar `FAIL`, saltar a la siguiente coincidencia dos veces, salir.
3. Contar las líneas de dos formas: `wc -l servidor.log`, y pasándole el archivo a `wc -l` por tubería (con `cat`). ¿Qué cambia en la salida?

**Comprobar:** las 3 primeras líneas empiezan con `2026-03-`, y los dos conteos:
```
300 servidor.log
300
```

## Parte 3 — Contar con `grep`

Responder con un comando cada una:
1. ¿Cuántas líneas tienen `ERROR`?
2. ¿Cuántas tienen `FAIL` como palabra completa?
3. ¿Cuántas líneas **no** son `INFO`?
4. Las tres primeras líneas con `FAIL`, con su número de línea.
5. ¿Cuántas líneas mencionan `disco`, esté en mayúsculas o minúsculas?

**Comprobar:** cinco respuestas (cuatro números y tres líneas). Tienen que coincidir con las del instructor.

## Parte 5 — Los "top"

Con `cut | sort | uniq -c | sort -rn`. Los campos van separados por **espacio**: fecha=1, hora=2, nivel=3, usuario=4, servicio=5, mensaje=6 en adelante.

1. Top de niveles: cuántas líneas hay de cada nivel, de más a menos.
2. Top de usuarios.
3. Los 3 servicios con más `ERROR` + `FAIL`.
4. Top de mensajes (el mensaje tiene espacios: campo `6-`).

**Comprobar:** cuatro listas. La primera tiene 4 filas (INFO, WARN, ERROR, FAIL), la segunda 5. Coinciden con las del instructor.

## Parte 6 — Guardar resultados

1. Guardar en `errores.txt` todas las líneas `ERROR`. Después **agregar** al mismo archivo todas las `FAIL`, sin pisar las anteriores.
2. Guardar en `criticos.txt` las líneas `ERROR` o `FAIL` **y a la vez** ver cuántas son, en un solo comando.
3. Ejecutar `ls /etc/hostname /noexiste` mandando la respuesta a `salida.txt` y la queja a `queja.txt`.
4. Poner en `/etc/motd` el texto `Servidor rhel01 - Lab 3` (necesita `sudo`; el `>` no va a funcionar).

**Comprobar:**
```bash
wc -l errores.txt criticos.txt
cat salida.txt queja.txt
cat /etc/motd
```
`errores.txt` y `criticos.txt` tienen la **misma** cantidad de líneas. `salida.txt` tiene `/etc/hostname`, `queja.txt` tiene el `No such file`. El `motd` muestra el texto.
